# ghostty-web-server

A local POSIX web server that opens a real shell session in your browser. The
server is now a native Zig binary, while the browser terminal frontend is built
as WebAssembly and bootstrapped by a tiny JavaScript loader.

The rewrite removes the Bun/Elysia/Preact stack and no longer depends on the
published `ghostty-web` npm package. The frontend boundary is shaped so the WASM
terminal module can be backed by `ghostty/libghostty-vt` directly; the current
renderer is intentionally minimal and text-grid based while the libghostty
renderer integration is completed.

## Quick start

```bash
zig build run
```

Then open <http://localhost:8080>.

## Configuration

| Env | Default | Notes |
|---|---|---|
| `PORT` | `8080` | HTTP + WebSocket port |
| `SHELL` | `/bin/bash` | Shell to spawn for each session |

## Development

```bash
zig build          # builds native server and client.wasm
zig build run      # runs the native server
```

The server serves:

- `/` — server-rendered page shell
- `/client.js` — browser bootstrap
- `/client.wasm` — Zig/WASM terminal module generated by `zig build`
- `/ws` — PTY WebSocket using JSON frames
- `/api/sessions` — active session list

## Build

```bash
zig build -Doptimize=ReleaseFast
```

The native executable and frontend artifacts are emitted under `zig-out/bin/`.
Release workflows build the same POSIX targets as before: Linux x64/arm64 and
macOS x64/arm64.

## Architecture

```
src/
  server/
    main.zig       native HTTP/WebSocket/PTY server
    app.zx         Ziex page-shell component source
    client_bootstrap.js browser bootstrap, WS client, minimal renderer
  client/
    terminal.zig   WASM terminal boundary
  shared/
    protocol.zig   shared wire protocol types
```

The server remains native because spawning a real shell PTY requires OS process
and terminal APIs. Only the browser frontend is compiled to WASM.

## Current frontend scope

This first Zig/WASM version intentionally ships a basic monospace text-grid
renderer. Full `ghostty-web` parity is still out of scope for v1, including
ligatures, advanced font fallback, Sixel/Kitty image protocols, and complete OSC
52 clipboard handling.

## Reverse proxy

HTTP and WebSocket share one port, and the client uses relative URLs, so it
works behind ngrok, nginx, or any proxy without extra config.

```nginx
location / {
    proxy_pass http://localhost:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

## Security warning

⚠️ **This server provides full shell access.**
Only use for local development and demos. Do not expose to untrusted networks.
